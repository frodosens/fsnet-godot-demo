# Shared generated UI theme

The bottom-dock generated runtime materials now supply the common PanelContainer, Button, OptionButton, text-entry, popup-menu and dialog panel styles. The main-menu buttons also use the approved normal/selected/disabled generated skins instead of their old flat hover rectangle. All text, focus, enabled states and commands remain real controls. This is a bounded material migration, not a new layout or a screenshot overlay.

Covered pages: home, load, network room, pause, story/dialogue, skills, consumables, equipment, save and confirmations. Editor forms inherit the same common theme. The existing main-menu background and approved portraits remain unchanged. Battle-dock measured geometry, path, lighting and static directional movement are unchanged.

Typography remains the bundled Noto Sans CJK Regular, Simplified Chinese face index 2, under assets/fonts/LICENSE.txt. It is the available licensed Chinese font; the generated concept lettering is not a font file. No new fonts were installed. Long descriptions retain wrapping and native font rendering.

Generated follow-up controls now skin CheckBox/CheckButton marks, the shipped horizontal slider, vertical scroll tracks/thumbs, OptionButton arrows and PopupMenu submenu indicators. Their native input semantics remain intact. Horizontal scrollbars, vertical sliders and OS window chrome do not yet have separately oriented specialty skins; no exact match is claimed for these unshipped variants. Skills, consumables and equipment lists now use the approved existing-content icon map: four skill icons, one bandage icon and nine equipment bases. Unknown Mod IDs retain native text without an invented icon; quality/affix variants reuse their base texture. No pixel-perfect match or full original art coverage is claimed.

Validation: Godot 4.6.3 on Linux, OpenGL Compatibility / Mesa llvmpipe. Full gameplay suite: 1638 checks and five server/two-client reconnect scenarios pass. Actual captures cover nine pages at 1280x800 and confirmation, items and network at 960x600. Existing menu/player-loop tests cover new game, story, skill/item use, AI, victory/defeat, save/load and confirmation/cancel. Physical touch/controller and Windows runtime remain unverified. Offscreen audio uses Dummy; no audio listening acceptance is claimed.

Reproduce the gallery using tests/capture_ui_gallery.gd with a graphics display; files go to /tmp. The existing record_bottom_dock.gd records actual mouse events for destination selection, cancel, confirm and wait. All review media remains outside Git. Library tool metadata reads work, but the refreshed local upload helper still fails during hosted-app tool discovery before preparation/write, including when files are staged under /workspace/scratch. No private URL or Git-media fallback was used.

The small-control fixture tests keyboard toggle, disabled checkbox, slider keyboard changes/disabled rejection, mouse-wheel scrolling and >=44 logical-pixel checkbox/slider hit areas at both viewport sizes (12 checks). Native assets are drawn at their intended sizes with authored slice margins; scroll content retains its full drag/wheel interaction area. Actual touch hardware remains untested. Theme-only changes do not modify deterministic rules.

Content-icon regression adds 28 checks: all mappings, attack reuse, unknown-ID fallback, actual skill keyboard activation, consumable binding, equipment variants and pane bounds at 1280x800/960x600. Icon tint for disabled controls retains alpha and readable silhouettes. Actual screenshots are kept under /tmp only. Shared Lua state, item identity, tooltips and command callbacks are unchanged.
