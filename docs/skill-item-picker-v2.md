# Shared skill/item picker V2

Based on main165f155c and runtime art cd83d5aa39ac446da38dab3acf4a1734f82bffa1. The approved design board stays outside Git. Library download failed in this implementation executor; layout follows the parent/art producer's inspected reference and the actual runtime PNGs, inspected locally.

The lower-right panel leaves the existing horizontal dock and character status visible. Four columns at normal widths, fewer in narrow safe regions; two full rows and a partial next row for larger lists. Small/empty lists shrink. The title displays actual count. The detail line remains outside scrolling content. Long text is truncated visibly with full supplemental tooltip; cost/cooldown/count and disabled reason are provided in the visible cell/footer, not exclusively by hover.

Skills come from the selected unit's allowed abilities (ordinary attack excluded); items use shared consumables and actual supplies. No sample entries were added to gameplay content. Touch drag, canceled touch, resize and scroll cannot activate on release. A valid click/tap or keyboard/controller accept enters existing map target mode directly; it does not submit a command or consume resources. Cancel/Esc/controller B returns to the action bar. Actor/step/session/reconnect changes invalidate the open picker; activation rechecks current affordability, cooldown/charges, inventory, movement restriction and command lock. Ordinary sync polling does not itself block choosing a target mode.

Art contract: assets/ui/picker_v2/panels/{picker_frame,cell_normal,cell_selected}.png, all four nine-slice margins16. Content padding is separate8x6. Existing native scrollbar styling is retained. Return uses the normal/selected cell art; disabled rows use color modulation and visible reason. Five128px icons use real IDs rally,strong_shot,ember,focus_bolt,bandage; healing_draught aliases bandage. Unknown Mod IDs fall back to the existing generic skill/item icon. Eleven additional icons are reusable assets only; they add no gameplay entries.

Testing includes0/1/8/9/12/37 fixtures, desktop1280x800/960x600, narrow safe-region fixture, mouse/touch+emulatedmouse deduplication, scroll, keyboard/controller, disabled/empty/cancel, scene exit, actor/reconnect invalidation, pending command and ordinary poll. Fixtures and diagnostic captures do not modify production content. Android touch is synthetic; no device/APK validation claimed.

Integration points: ui/battle_hud.gd owns picker entries/modal lifecycle and reuses main.select_mode; ui/bottom_dock.gd leaves the dock visible but disables its actions while picker is open. main.gd, camera, shared Lua/native rules, save/checkpoint files and health-width behavior are unchanged.

Validation result: 1,402 relevant headless checks,126 graphical picker checks,27 checks in the existing three-process real-fsnet target-confirmation suite passed. The latter preserves existing synchronization/confirmation behavior; picker poll/command-busy tests are controlled local fixtures, not a claim that the entire picker was exercised across three remote devices.
