# Character details interface (integration in progress)

Bottom status `资料` and the original bottom portrait open the same selected-player browser. The right eye-strip roster remains a direct actor selector. This interface uses the generated character_details_v1 panels with their slice margins, original character portraits, and viewport-safe insets. It does not alter camera or battle rules.

Tabs browse actual attributes, skills, shared consumables, and nine equipment slots. Skill/item rows show full descriptions without casting or consuming. The scrollable full-description layer returns to the underlying tab and scroll position. Equipment changes use the existing authoritative `equip` command; preview executes that command on an isolated Lua snapshot, never mutating the live runtime. During combat equipment remains locked, and owned or slot-incompatible items cannot be taken. Repeated equip of the already equipped UID is disabled.

The modal owns mouse/touch gestures including outside dismissal. Drags, canceled gestures and multiple fingers cannot activate controls. Native touch release bookkeeping is retained so the following map tap is not swallowed. An unchanged-state network poll does not rebuild the list or cancel a held touch. Session generation, actor or presentation changes close stale contexts; actual state changes refresh data while retaining tab/scroll. A dedicated three-process fsnet test covers actual in-flight polls, accepted/rejected equipment commands, remote ownership changes, unchanged-state Runtime replacements and reconnect invalidation.

Level/XP uses the progression runtime contract: current = xp - xp_floor; required = xp_next - xp_floor; zero required displays max level. Thresholds and growth formulas are never duplicated in the UI. Missing fields display unavailable rather than guessed values. The approved concept could not be downloaded through the supported Library transfer (technical failure, one retry exhausted); the actual runtime panel package was fetched and visually inspected. Final joint review remains required before publication.

Local tests cover authoritative isolated equipment previews, raw touch/emulated mouse, four viewport proportions, actual equipment once, fulltext Chinese wrap, safe areas, reconnect invalidation, pending request guard and no map/camera click-through. Screenshots stay outside Git. No Android device validation or APK is included.

Run `python tests/run_character_details_network.py` with the existing native bridge and fsnet library path. Set `AMBER_GRAPHICAL=1` to drive the same real controls with rendering enabled. The independent observer compares the exact authoritative state hash and inventory after identical JSON numeric normalization; this is not a mocked transport.
