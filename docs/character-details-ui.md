# Character details interface — v2 visual reconstruction candidate

This isolated UI change is based on main `365db99c27f6ca71e9148fffc524790877552eca`. The unit-definition/instance refactor is not included. It is not part of the frozen v7 or the refactor v8 build.

The v2 asset source is `f1884c6fc790cbdbf33f7239fffcfd789b92361c`, with the approved 1672×941 reference measurements in `assets/ui/character_details_v2/layout_contract.json`. `ui/character_details_geometry.gd` aspect-fits that canvas into the HUD safe rect. The desktop modal, identity card, attributes, traits and current-equipment panels use the measured bounds. The original portrait uses a 323:406 content rectangle and aspect-cover cropping, never nonuniform scaling. Four tabs, separate close/return controls, typography hierarchy and ten icon/value cells replace the previous single text column. Health/mana retain current and maximum values; the action cell reports the runtime's spent flag, not a guessed action budget.

Each texture uses its manifest caps and content padding. In particular, tab caps are 12 px, not the old blanket 24 px. The complete-description and equip controls remain in the reserved footer so they are reachable after scrolling. The footer hint shifts beside these retained functional controls. XP remains based on runtime `xp_floor`/`xp_next`; no progression formula lives in presentation code.

Below 600 physical safe-area pixels, or when the reference body font would fall below 16 physical pixels, the compact layout keeps header, four tabs, close and footer fixed. Only content scrolls. The portrait retains its aspect and reserves separate name/class/level/XP rows. When the remaining main content width is below 900 physical pixels, current equipment follows traits in the content scroll. Nested scrollers ignore invisible/clipped regions and fall back to the outer content scroll when their own content does not overflow.

Existing real-data adapters, shared inventory, authoritative equip submission, isolated Lua equipment previews, combat/pending/ownership guards, session invalidation, canceled/multifinger dismissal protection and native touch-release bookkeeping are retained. A state poll does not rebuild unchanged lists. No battle rules, content data, native bridge or network protocol changed.

Validation: existing UI, model, progression and touch suites; updated visible-traits scrolling regression; new five-resolution layout and narrow-screen nested-touch tests; and the three-process real fsnet equipment/poll/reconnect test. Graphical captures use Godot 4.6.3 / Mesa llvmpipe at 1280×800, 1200×540 with a notched safe-area fixture, and 1672×941 for reference alignment. Mouse and touch press/release events open the page and switch all tabs; only the current tab is highlighted, and browsing does not mutate the battle snapshot. Screenshots and capture scripts stay outside Git.

The exact original reference could not be downloaded into this executor through the supported Library helper. Reconstruction therefore uses the native art worker's measured contract and inspected v2 component pixels. Local screenshots are reviewed for rendering defects, but final comparison against the original pixels still belongs to the native/root visual reviewer. Library screenshot upload remains blocked by a tools-discovery network failure. No Android-device validation, APK, merge to main or final visual approval is claimed.
